## 1. ご提案の概要
「ヨヤクル」は、AIによる電話受付とチャット予約、Googleカレンダー連携を一体化した予約サービスです。伏見整体院様に第一号の導入先としてご協力いただき、実際の受付業務に合わせて使いやすさを改善します。

目指すのは、施術中の電話対応を減らし、営業時間外にも予約を受け付け、予約の確認を一か所にまとめることです。導入効果は試験運用で測定し、継続利用を判断いただきます。

## 2. 解決したい課題と確認事項
| 想定する課題 | 提供する対応 | 導入前に確認すること |
|---|---|---|
| 施術中に電話へ出られない | AIが希望日時とメニューを聞き取り予約受付 | 不在着信件数、現在の折り返し方法 |
| 営業時間外の予約機会を逃す | 営業時間外も電話・チャットで受付 | 受付対象時間、当日予約の締切 |
| 電話対応で施術が中断する | 定型的な予約受付をAIに任せる | 電話の内容と平均対応時間 |
| 複数の受付経路で予定が重複する | 電話・チャット共通の予約台帳で管理 | 既存予約サイト、紙台帳との併用 |
| 新しい管理画面が負担になる | Googleカレンダーで予定を確認 | 利用アカウント、担当者別カレンダー |

※上記は課題の仮説であり、貴院の実態として断定するものではありません。

## 3. 初回導入で提供する機能
### AI電話予約
希望日時、施術メニュー、お名前、連絡先を聞き取り、空き枠を確認します。満席時は別の日時を提案し、予約内容を復唱して了承を得たうえで確定します。判断できない内容は折り返し依頼として記録します。

同じ番号への複数の着信にも、契約・システムの同時対応上限内で個別に対応します。初期の上限は想定件数と負荷試験により設定します。

### チャット予約
貴院のWebサイト等からチャットを開き、電話と同じ予約枠に申し込めるようにします。営業時間、所在地、料金などの案内は、貴院に確認いただいた情報だけを使用します。

### Googleカレンダー連携
確定した予約をカレンダーへ登録し、既存の予定を予約不可時間として取り込みます。予約データの本体はヨヤクルで管理します。同期エラーは管理者に通知し、再処理できるようにします。

初回は予約の変更・取消をヨヤクル側で行う運用とし、Google側で予約を直接編集した場合の扱いは導入時に決めます。「完全連携」の範囲を明文化し、同時編集時の競合を検出します。

### 管理・通知・月額課金
予約一覧、電話対応結果、折り返し依頼、利用時間を確認できます。通知先は協議して設定します。サービス利用料はStripeで月額決済する構想です。来院者からの施術代のオンライン回収は、初回導入の対象外です。

## 4. お客様の利用イメージ
1. お客様が電話する。「明日の夕方、予約できますか」
2. AIが希望する施術メニューを確認する。
3. 所要時間、営業時間、空き枠を照会し、候補を案内する。
4. お名前と連絡先を聞き取る。
5. 「○月○日17時、○○コース、お名前は○○様でよろしいですか」と復唱する。
6. お客様が了承し、システムへの登録成功後に予約確定を案内する。
7. カレンダーと管理画面に予約が表示される。

※日時・メニューは説明用です。実際の施術内容や営業時間を示すものではありません。

## 5. 無理なく始める運用
初回は、所要時間と料金が明確なメニューの新規予約から開始します。変更・取消、例外的な要望、詳しい施術相談は折り返し受付とします。症状の診断や施術可否の判断をAIに任せず、院の担当者につなぎます。

既存の電話番号を残す場合は、店舗専用のAI受付番号へ転送する方式を検討します。電話会社の転送条件、同時転送数、転送料、番号取得条件を確認して決定します。転送先から元の番号へ戻してループしない設計にします。

電話の冒頭でAI受付であることを案内します。通話記録の保存範囲、保存期間、閲覧権限を事前に合意し、必要な情報だけを保管します。

## 6. 初号店としての進め方
| 段階 | 期間の目安 | 実施内容 |
|---|---|---|
| 業務確認・設計 | 1週間 | メニュー、受付ルール、既存予約経路、電話契約の確認 |
| 初期設定・試作 | 2〜3週間 | 予約台帳、Google接続、電話・チャットの設定 |
| 院内テスト | 1週間 | 聞き間違い、満席、同時予約、切断、同期失敗を確認 |
| 限定した実運用 | 4週間 | 営業時間外などから開始し、毎週改善 |
| 継続判断 | 実証終了時 | 実績と費用を確認し、本運用の範囲を合意 |

開発着手から継続判断まで約8〜9週間の仮計画です。番号取得・接続審査・既存システム調整により前後します。実運用はテスト合格後に開始し、障害時は従来受付へ戻せるようにします。

## 9. 効果の測定と継続判断
導入前に可能な範囲で1〜2週間の電話件数・不在着信・対応時間を記録し、実証中と比較します。

| 指標 | 確認する内容 |
|---|---|
| 予約受付実績 | AI対応件数、確定件数、営業時間外の確定件数 |
| 受付品質 | 誤登録、重複予約、聞き直し、折り返し件数 |
| 業務負担 | 電話対応時間と施術中断の変化 |
| お客様の利用状況 | 途中離脱、苦情、利用者の感想 |
| 費用 | 1件当たりの通話時間、月額利用料、超過見込み |

本稼働の最低条件は、院内テストで重大な誤予約・重複予約がなく、例外時の折り返しと障害時の切替が機能することです。実証中に重大な誤予約が発生した場合は、自動確定を止めて原因を修正します。

費用対効果は「追加で獲得できた予約の限界利益＋削減できた受付負担」と利用料を比較します。例えば予約1件の限界利益を3,000円と仮定すると、月額14,800円は追加予約5件でおおむね相当します。これは説明用の計算で、貴院の利益や成果を保証するものではありません。

## 10. 初回打ち合わせで決めたいこと
- 対象となる施術メニュー、所要時間、担当者数、予約間隔

- Googleカレンダー利用状況と、予約管理の正本を移す範囲
- AIに任せる時間帯、例外時の連絡先と折り返し手順
- 実証料金、利用上限、開始希望時期、継続判断の条件
