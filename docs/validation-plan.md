# 検証と開発手順

整理日：2026年11月4日／提案段階

## 1. 音声の技術検証

OpenAI音声APIと電話番号を接続し、日本語で実際に予約会話を行う。まず架空の整体院・架空顧客でテストし、実店舗への着信転送は院と運用を合意してから開始する。

確認：応答速度、割り込み、数字・氏名・日時、曖昧な表現、聞き直し、通話切断、予約成功／失敗の案内、同時通話、利用量ログ。採用モデルや回線は品質と原価の両方で決める。

## 2. 共通予約API

営業日・メニュー・所要時間・資源制約を実装する。仮押さえ、同時予約、冪等性、仮押さえ期限、テナント分離を検証する。電話とチャットで同じAPIを使う。

## 3. Google連携・店舗管理

OAuth接続、カレンダー選択、外部予定取り込み、予約の反映、同期失敗と競合の復旧を実装する。Googleでの直接編集の扱いを決める。

## 4. 課金・運用

Stripe課金、利用量メーター、上限通知、支払失敗時の扱いを決める。監視・折り返し通知・保存期間・問い合わせ対応・障害時の受付切替を整備する。

## 5. 初号店での実証

伏見整体院の現状をヒアリングして対象メニューと時間帯を絞る。院内テスト合格後に4週間の実証を提案する。AI対応件数、確定件数、誤予約・重複、折り返し、施術中断、顧客の感想と原価を記録し、継続利用を判断する。

## 未決事項

電話契約主体・番号提供条件、採用モデル、技術スタック、店舗ごとの同時対応数、カレンダー正本の運用、料金・最低利用期間・初期設定費、クライアントの契約・事例公開可否。
